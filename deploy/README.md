# Развёртывание

Установка на чистый сервер Ubuntu/Debian одной командой.

## Быстрый путь

```bash
ssh root@ВАШ_СЕРВЕР

git clone -b claude/epic-mccarthy-sl30hz https://github.com/AntonSergeevich/midi_to_tab /tmp/nasluh
cd /tmp/nasluh/deploy

DOMAIN=naslux.ru EMAIL=ваша@почта bash install.sh
```

Скрипт делает всё: ставит пакеты, заводит отдельного пользователя,
разворачивает код и окружение Python, генерирует ключи, настраивает
службу, получает сертификат, поднимает nginx, включает брандмауэр и
ежедневную уборку диска.

### Если DNS ещё не настроен

Установка **не прервётся**: сайт поднимется на HTTP и будет доступен по
адресу сервера, а сертификат возьмёте потом одной командой:

```bash
DOMAIN=naslux.ru EMAIL=ваша@почта bash /opt/nasluh/app/deploy/certbot.sh
```

Проверить, готов ли DNS:

```bash
dig +short naslux.ru    # должен вернуть адрес сервера
```

Пустой ответ означает, что записи ещё не созданы или домен не делегирован
(не прописаны NS-серверы у регистратора). Обновление занимает от 15 минут
до нескольких часов.

## Что где лежит

| Путь | Что |
|---|---|
| `/opt/nasluh/app` | код |
| `/opt/nasluh/venv` | окружение Python |
| `/opt/nasluh/data` | база, загрузки, результаты |
| `/opt/nasluh/nasluh.env` | настройки и ключи, права 600 |
| `/etc/systemd/system/nasluh.service` | служба |
| `/etc/nginx/sites-available/nasluh` | сайт |

## Повседневное

```bash
systemctl status nasluh --no-pager   # состояние (без пролистывания)
journalctl -u nasluh -f        # логи вживую
systemctl restart nasluh       # перезапуск

# обновление после git push
cd /opt/nasluh/app && git pull && systemctl restart nasluh

# ключ администратора
grep MIDI2TAB_ADMIN_KEY /opt/nasluh/nasluh.env
```

## Тяжёлые части

Разделение на партии и распознавание текста тянут PyTorch (около 2 ГБ) и
ставятся отдельно — когда убедитесь, что памяти хватает:

```bash
bash /opt/nasluh/app/deploy/install_separation.sh
/opt/nasluh/venv/bin/pip install --no-cache-dir faster-whisper
systemctl restart nasluh
```

**Не ставьте demucs напрямую через pip.** На Linux он тянет torch со всем
набором CUDA — около двух гигабайт драйверов для видеокарты, которой на
сервере нет. Диск на 40 ГБ это переполняет. Скрипт выше ставит сборку
для процессора (примерно 200 МБ) и заранее проверяет свободное место.

Веса моделей скачиваются при первом обращении: Demucs около 300 МБ,
Whisper small около 480 МБ. Первый разбор поэтому будет заметно дольше.

## Решения, которые стоит знать

**Один рабочий процесс.** В юните стоит `--workers 1` намеренно. Разбор
идёт в пуле потоков внутри процесса, и каждый лишний процесс множит и
пул, и память под PyTorch. На сервере с 4 ГБ два процесса кладут машину
по памяти, а не ускоряют работу.

**Предел памяти.** `MemoryMax=3G` в юните: если разбор съест всё, systemd
убьёт только сервис, а не даст ядру выбирать жертву по всему серверу.

**Предел загрузки.** `client_max_body_size 80m` в nginx. Без этой строки
nginx режет тело запроса на одном мегабайте, и загрузка падает с 413
раньше, чем приложение успеет объяснить причину. Значение должно быть не
меньше `MIDI2TAB_MAX_MB`.

**Долгие ответы.** `proxy_read_timeout 600s`: разбор идёт минутами, а по
умолчанию nginx обрывает ожидание на минуте.

**Не от root.** Служба работает от пользователя `nasluh` с доступом
только к своим папкам.

**IPv6 не включён.** Если на сервере он выключен, строка `listen [::]:80`
роняет nginx целиком. Когда IPv6 есть — добавьте такие строки рядом с
каждым `listen` и проверьте `nginx -t`.

## Уборка диска

Партии одной песни в WAV весят около 250 МБ: сорокагигабайтный диск они
заполняют примерно за сто шестьдесят треков. Таймер `nasluh-cleanup`
раз в сутки удаляет загрузки и партии старше двух недель, **оставляя
результаты** — аккорды, табы и MIDI весят килобайты, и ради них человек
приходил.

Если свободного места меньше 12%, сроки автоматически сокращаются вчетверо.

```bash
systemctl list-timers nasluh-cleanup     # когда сработает
systemctl start nasluh-cleanup.service   # запустить сейчас
journalctl -u nasluh-cleanup             # что удалено
du -sh /opt/nasluh/data/*                # что занимает место
```

## Что проверено

Конфигурация nginx проверена `nginx -t`, юниты — `systemd-analyze verify`,
скрипт уборки — на подготовленных данных (старое удалено, результаты
сохранены), полный цикл загрузки — настоящим запросом через nginx:
файл 6,6 МБ прошёл, задание создалось, аккорды определились.

нему, ни к домену.
