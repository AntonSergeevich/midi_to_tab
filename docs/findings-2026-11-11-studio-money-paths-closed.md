## Проверено по чек-листу из прошлого прогона — гонок не нашлось, список платных ручек закрыт

Прошлый прогон (10.11) оставил пунктом на сегодня: пройтись по
оставшимся простым ручкам Студии (`/api/studio/upload`,
`/api/studio/{id}/reference`, `/api/studio/{id}/tempo`,
`/api/studio/{id}/shift`) тем же вопросом про гонку
проверка-потом-действие без лока + списание денег.

Прочитал каждую из четырёх в `web/app.py`:

- **`POST /api/studio/upload`** — свой трек в «Мои треки», `"charged": 0`,
  только дневной лимит загрузок (`UPLOADS_PER_DAY`). Денег нет — гонка
  невозможна по определению.
- **`POST /api/studio/{id}/reference`** — вставка эталонного листа
  аккордов для сверки моделей, не платное действие вовсе.
- **`POST /api/studio/{id}/tempo`** — свой темп/сильная доля вместо
  автоопределения, пишет только `tempoFix` в `result`, без создания
  платного задания.
- **`POST /api/studio/{id}/shift`** — тональность и темп, явно
  прокомментировано в коде как "на своём сервере, бесплатно"
  (`"charged": 0`, `engine: "local"`).

Все четыре — бесплатные действия на собственном сервере, без создания
платного задания и без списания денег. Гонка "проверка-потом-действие +
списание" здесь структурно невозможна, лок не нужен.

**Итог**: чек-лист "проверка-потом-действие без общего лока + списание
денег" по всем путям `web/app.py`, создающим `storage.create_job`, теперь
пройден целиком (тянется с находок 06.11, 07.11, 08.11, 10.11 и этого
прогона): `/tabs`, `/stems` (результат и свежая загрузка через
`/api/studio`), `hit/{wav,karaoke,12dorogek}`, `/extend` (оба движка),
клонирование голоса, `/api/studio` (create/restyle/enrich/continue/
stems-с-нуля) — защищены локом; `/shift`, `/tempo`, `/reference`,
`/upload`, `/notes`, `cover_upload` — бесплатны и защиты не требуют.
Дальше по этому направлению возвращаться стоит только если появится
новая платная кнопка.

## Что ещё проверено без находок

Прочитал построчно оставшиеся небольшие файлы фронтенда, которые прошлый
прогон (05.11) отметил как непрочитанные: `admin.js` (444 строки),
`soundfx.js` (362), `lyricstags.js` (200), `metro_sounds.js` (151),
`karaoke.js` (71), `consent.js` (54), `i18n.js` (154). Конкретных багов,
которые можно было бы безопасно починить и проверить тестом, не нашёл:

- `admin.js` — единственное отмеченное: `value="${u.note || ''}"` не
  экранирует кавычки в заметке админа (самострел в атрибуте HTML), но
  страница видна только самому владельцу/админу — цена находки намного
  меньше риска трогать разметку админки вслепую без возможности открыть
  её в браузере.
- `soundfx.js` — сложная, тонко откалиброванная цепочка Web Audio
  (эквалайзер, лимитер, выравнивание громкости, "8D") с несколькими
  задокументированными правками по жалобам владельца именно на слух
  (29.10, 30.10, 01.11). Без возможности послушать результат в браузере
  правка здесь — риск без проверки, а не находка.
- `lyricstags.js` — эвристика разметки текста песни (куплет/припев/
  бридж) без эталонного набора и без тестов вообще; нашёл теоретически
  спорный край (`label()`: порядок `forEach` может дать два отдельных
  "припева" вокруг одного `pre`-куска при цепочке из нескольких hook-
  кусков подряд), но это не воспроизведённый баг на реальном тексте, а
  умозрительный крайний случай эвристики без осмысленного "правильного"
  ответа — не стал трогать без примера, на котором видно, что текущее
  поведение хуже предложенного.
- Остальные (`metro_sounds.js`, `karaoke.js`, `consent.js`, `i18n.js`) —
  без замечаний.

## Что не трогал и почему

- **Качество распознавания аккордов** — та же ситуация, что и в
  предыдущих нескольких прогонах: открытая гипотеза HPSS/BS-RoFormer
  ждёт GPU (`CLAUDE.md`, `scripts/compare_separation.py`), численная
  проверка на GuitarSet уже сделана (22.10) и не дала изменений. Нашёл,
  что `LABEL_QUALITIES`/`DIATONIC_MINOR`/`DIATONIC_MAJOR` в
  `audiochords.py` (шаблонный, не нейросетевой путь) знают только о
  простых трезвучиях для подсказки тональности, а не о септаккордах —
  но это калиброванная на семи размеченных песнях константа
  (`THIRD_MARGIN`, `DIATONIC_BONUS`), трогать её без доступа к тому же
  калибровочному набору — риск регресса вслепую, именно то, что мандат
  просит не делать.
- **Код GPU-воркера** (`worker/handler.py` restyle/create/enrich) —
  теперь реально покрыт тестами локально (`runpod` поставился,
  `test_worker_handler.py` выполнился: 467 passed вместо 461+1 skip) —
  но это не новая правка, просто окружение песочницы в этом прогоне
  позволило поставить зависимость, которую предыдущие прогоны (включая
  10.11) по разным причинам не ставили. В CI (`unit-tests.yml`) этот
  файл не пропускается уже с 03.11 (`27cfffe`) — находка не новая.
