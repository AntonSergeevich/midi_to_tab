# Прогон 03.11.2026

## Контекст: два предыдущих прогона (31.10, 02.11) отметили один и тот же пробел

`tests/test_worker_handler.py` целиком пропускает себя
(`pytest.importorskip("runpod")`), если пакет `runpod` не установлен --
а он не входит ни в `requirements-web.txt`, ни в `dev`-экстру
`pyproject.toml` (нужен только самому GPU-воркеру в его собственном
Docker-образе, не веб-приложению). Прогон 31.10 проверил существующие
тесты вручную (аргументы/порядок вызовов совпадают с реализацией) и
отложил включение до момента, когда `runpod` "станет доступен в
тестовом окружении" -- прогон 02.11 повторил ту же рекомендацию.

## Проверено: пакет ставится и тесты реально проходят

`pip install runpod` в этой песочнице отработал без ошибок за несколько
секунд (чистый Python-пакет, тяжёлых ML-зависимостей типа torch нет --
только `boto3`, `aiohttp`, `fastapi` и подобные). После установки
`tests/test_worker_handler.py` перестаёт пропускаться и все 6 тестов
(3 engine на `test_restyle_rejects_unsupported_engine_*` + 3 на
`test_restyle_accepts_known_engines_*`) реально проходят против
настоящего тела `worker.handler.restyle()`, не мока.

То есть пробел был не "runpod недоступен в принципе", а просто "runpod
не входит в список зависимостей для тестов" -- тестовому окружению
(что в CI, что в этой песочнице) ничего не мешало его поставить, никто
не пробовал.
