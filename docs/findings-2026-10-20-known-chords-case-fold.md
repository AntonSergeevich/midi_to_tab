# Находка 2026-10-20: список известных аккордов от человека сворачивал мажор в минор

Дата: 2026-10-20. Автономный прогон по мандату из `CLAUDE.md`.

## Исправлено: `_pick_names()` сравнивал имена без учёта регистра,
## хотя собственный докстринг обещал обратное

На сайте есть возможность подсказать разбору круг аккордов песни заранее
(поле «известные аккорды», `web/app.py` -> `options["allowed"]` ->
`web/jobs.py` -> `audiochords.detect_from_audio(..., allowed=...)`) --
тогда второй проход подбирает подпись только среди названных аккордов, не
среди всех шаблонов. Если список назван, он подменяет круг аккордов
ПОЛНОСТЬЮ: никакое другое качество на этом тоне уже не может быть выбрано.

`midi2tab/audiochords.py: _pick_names()` разбирает этот список. Его
собственный докстринг прямо говорит: "регистр качества сохраняем (m --
минор, M -- нота), поэтому сравнение не по lower()". Код делал ровно
наоборот:

```python
table = {name.lower(): i for i, name in enumerate(names)}
...
index = table.get(text.lower())
```

Оба конца сравнения сворачивались в нижний регистр -- то есть "AM" и "Am"
становились одной и той же строкой `"am"`. "AM" (ля МАЖОР заглавной буквой
-- обычная человеческая привычка выделять аккорд капсом) тихо
превращался в "Am" (ля минор):

```
>>> _pick_names(names, 'AM')
[154]
>>> names[154]
'Am'
>>> _pick_names(names, 'A')
[153]          # другой индекс -- это другой, правильный, аккорд (мажор)
```

Поскольку список полностью заменяет автоматический подбор, ошибка не
локальная: правильный ля мажор во всей песне после этого не мог быть
подписан нигде -- человек, который пытался ПОМОЧЬ разбору точным списком
аккордов, получал ухудшенный результат именно в том месте, которое сам
назвал.

### Фикс

`midi2tab/audiochords.py: _pick_names()` -- убраны оба `.lower()`:
таблица имён строится из `names` как есть, поиск -- по `text` как есть.
Сравнение регистра букв `m`/`M` теперь действительно решает мажор или
минор, как и было задумано докстрингом с самого начала; остальная
нормализация (первая буква -- заглавная, бемоли -- в диезы) не менялась.

### Тест

`tests/test_engine.py::test_chord_list_is_case_sensitive_about_major_vs_minor`
-- проверяет, что `"Am"` и `"A"` дают разные, верные индексы, а `"AM"`
(неоднозначный регистр) не подставляется молча под минор, а просто не
находится. Старый тест `test_chord_list_from_user_is_parsed` (разбор
`"Dm, Bb, F, C"` и `"dm bb"`) остался зелёным без изменений -- фикс не
трогает нормализацию регистра первой буквы и бемолей, только финальное
сравнение имени целиком. Полный прогон (404 теста, было 403) зелёный.

## Как найдено

Фоновый обход файлов, которые не разбирались детально в прошлых раундах
(`web/app.py`, `web/studio.py`, `web/releases.py`, `web/voicefx.py`,
`web/billing.py`, `web/jobs.py` целиком, а также `midi2tab/shapes.py`,
`arrange.py`, `gp5out.py`, `beatnet.py` -- уже калиброванная логика без
новых находок). Рассмотренные и отклонённые кандидаты:

- `web/studio.py`: подозрение на несовместимую комбинацию `keep_vocals` +
  движок YuE2 по цене -- не воспроизводится, `web/app.py` принудительно
  выключает `keep_vocals`, когда движок не `mureka`.
- `web/app.py: api_studio_voice` (денойз/подстройка/отмена): проверка
  TOCTOU в очистке `dst` -- защищена короткой замыкающей проверкой
  (`op != "undo" and os.path.isfile(dst)`), гонки нет.
- `midi2tab/shapes.py`: баррэ-аккорды уже чинились трижды в прошлых
  раундах; перечитан целиком ещё раз -- новых случаев того же класса
  ошибки не нашлось.

## Что не трогал и почему

- `deploy/cleanup.py`: в сортировке по `stat()` при одновременном внешнем
  удалении файла теоретически возможен TOCTOU -- но в текущей схеме
  (один таймер, нет параллельного внешнего удаления) не воспроизводится
  и не стоит автономной правки вслепую.
- `web/voicefx.py` (автотюн/PSOLA): новая плотная DSP-логика -- проверена
  только на отсутствие крашей/индексных ошибок; оценка качества звучания
  нужна человеческому уху, а не текстовому агенту (мандат прямо это
  оговаривает).

## Что стоит сделать в следующий прогон

- Подсказка аккордов человеком покрыта тестом только на уровне
  `_pick_names()`; стоило бы когда-нибудь добрать end-to-end тест через
  `web/app.py` -> `allowed`, чтобы проверить весь путь целиком, а не
  только разбор строки.
- Прежние открытые направления (`findings-2026-10-19`) остаются
  актуальными: накопление статистики `tuned` vs `main` на боевом трафике
  через `web/benchmark.py` и доведение словаря шаблонного разбора
  (`LABEL_QUALITIES`) до септаккордов -- обе задачи крупнее одной правки
  и нужны либо боевые данные, либо отдельное решение.
