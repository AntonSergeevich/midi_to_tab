# Находка 2026-10-27: свод сверки моделей аккордов видел только свои эталоны

Дата: 2026-10-27. Автономный прогон по мандату из CLAUDE.md. Открытый
пункт из находок 10-25 («накопление статистики tuned vs main на боевом
трафике») — наконец сделан.

## Симптом

У `/api/studio/benchmark` (своя страница «Сверить с эталоном» в Студии)
не было парного взгляда «по всем людям»: пользователь видел средний
итог моделей (`main`/`tuned`/`nokey`/`ens`/...) только по СВОИМ
вставленным листам аккордов. Решение «переключить сайт на `tuned` по
умолчанию» или «добавить `ens` в прод» при этом принималось либо по
калибровочному набору из семи песен владельца (не в репозитории, см.
`findings-chord-quality.md`), либо вообще без цифр с реального трафика —
хотя сами цифры уже копились: любой человек со «Студией» может вставить
эталон под своей готовой работой, и это именно разметка на настоящих,
разных треках, а не искусственный набор.

## Фикс

- `web/storage.py::reference_jobs()` — новый метод: все работы (любого
  пользователя), у которых есть хоть один вставленный эталон
  (`json_extract(result, '$.reference') IS NOT NULL`), с почтой через
  `JOIN` — чтобы в своде было видно, не тянет ли итог один активный
  человек, вставивший много эталонов под одни и те же песни.
- `web/benchmark.py::aggregate()` — вынесена общая сборка строк и
  средних (была только внутри `api_studio_benchmark`); необязательный
  параметр `labels` добавляет поле `who` к строкам — для админского
  свода, старое поведение (без `who`) не меняется.
- `web/app.py::api_admin_benchmark()` — новый эндпоинт
  `GET /api/admin/benchmark` (`require_admin`): тот же итог, но по
  `storage.reference_jobs()` вместо `storage.user_jobs(текущий)`.
  `api_studio_benchmark` отрефакторен на тот же `aggregate()`, формат
  ответа не поменялся (проверено существующим тестом).
- Карточка «Распознавание аккордов» в `web/admin.html` +
  `loadBenchmark()` в `web/static/admin.js`: таблица моделей со
  столбцом «Кто» (почта или «без почты» для анонимных), те же подписи
  моделей, что в Студии (`MODEL_NAME`), чтобы не плодить два словаря
  расходящихся названий по сути (разошлись только именем константы —
  `admin.js` не делит модуль с `studio.js`).

## Тест

`tests/test_benchmark.py::test_reference_endpoints` — расширен: второй
(анонимный) пользователь со своим эталоном не виден в чужом
`/api/studio/benchmark` (там только свои строки), `/api/admin/benchmark`
без прав админа отвечает 403, с правами — показывает оба эталона и
честную подпись «без почты» (оба пользователя анонимные, почты нет —
подпись не выдумывает её). Полный прогон — зелёный (409/409 до этого
пункта, тот же тест-файл).

## Что дальше

- Пока эталонов на сайте мало (почти все — от владельца на калибровке),
  свод будет в основном показывать его же данные под другой подписью.
  Ценность появится, когда разметка начнёт копиться от обычных людей со
  «Студией» — сейчас для этого ничего больше не нужно делать, просто
  ждать трафика.
- Решение «переключить прод на `tuned`/`ens`» всё ещё не принято — для
  него понадобится не только этот свод, но и достаточно разметки за
  скобками калибровочных семи песен (см. `findings-chord-quality.md`,
  находка 10-22 про GuitarSet).
