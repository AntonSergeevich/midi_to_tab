# Находка 2026-10-14: чужие треки в офлайн-кэше после входа через OAuth

Дата: 2026-10-14. Автономный прогон по мандату из `CLAUDE.md`. Разбирал
вчерашний коммит `6df62a6` («Offline multitrack, installable app,
favorites») — свежая, ещё не проверенная область: сервис-воркер (`sw.js`).

## Исправлено: GET-вход через Яндекс/VK не чистил память устройства

`web/static/sw.js` намеренно сбрасывает три кэша Cache API (`PAGES`, `DATA`,
`AUDIO` — страницы, ответы `/api/...` и звук дорожек мультитрека) при входе,
выходе и регистрации: функция `forgetUser()`, «Чужое и личное не храним».
Но срабатывала она только для **POST**-запросов на
`/api/auth/(login|logout|register)`:

```js
if (request.method !== 'GET') {
  if (/^\/api\/auth\/(login|logout|register)/.test(url.pathname)) event.waitUntil(forgetUser());
  return;
}
if (NEVER.test(url.pathname)) return;
```

Вход через Яндекс/VK устроен иначе (`web/app.py:api_oauth_callback`,
`@app.get("/api/auth/{provider}/callback")`): провайдер возвращает браузер
на этот адрес **GET**-ом, и сервер уже там меняет куку `uid` — то есть это
такая же смена личности, как обычный вход по паролю, просто другим HTTP-
методом и другим путём (`/callback`, а не `/login`). Эта ветка попадала под
`NEVER` (там есть общий префикс `api/auth`) и просто не перехватывалась
сервис-воркером — `forgetUser()` не вызывался вовсе.

### Почему это не косметика, а утечка приватных данных

`DATA`-кэш хранит, в частности, ответ `/api/studio` (список треков со
статусами, названиями, обложками) — у него нет общего с `NEVER` исключения,
только auth/admin/pay/webhook/health. `AUDIO`-кэш хранит реальные байты
звука дорожек (`mix.js: audioBytes()`). Ключ кэша — сам URL, один на всех
пользователей (`/api/studio`, `/api/studio/file/<job>/<name>`), а не
что-то, завязанное на личность.

Сценарий: общий компьютер (студия, репетиционная точка, семейный ноутбук).
Человек А открывает Студию, что-то слушает — `PAGES`/`DATA`/`AUDIO`
заполняются его треками. Он НЕ нажимает «Выйти» явно (просто закрывает
вкладку или передаёт устройство), человек Б входит через Яндекс/VK. Вход
происходит, но кэш не чистится. Если у Б после входа на секунду медленная
сеть — `fromNetworkFirst` в `sw.js` ждёт сеть **4 секунды** (`WAIT = 4000`),
и при таймауте отдаёт то, что лежит в кэше под тем же URL, то есть данные
человека А (список его треков, обложки), пока не придёт свежий ответ сети.
Тот же путь воспроизводим без сети вообще — Б уходит в офлайн сразу после
входа, видит кэш А.

### Фикс

Добавлена отдельная проверка для GET на `.../callback` ДО возврата по
`NEVER`, вызывающая тот же `forgetUser()`, каким пользуются обычный
логин/логаут/регистрация:

```js
if (/^\/api\/auth\/[^/]+\/callback/.test(url.pathname)) event.waitUntil(forgetUser());
if (NEVER.test(url.pathname)) return;
```

Сам запрос `.../callback` по-прежнему не кэшируется и не перехватывается
(`NEVER` дальше работает как раньше) — меняется только то, что он ещё и
стирает три кэша предыдущего человека, прежде чем новый начнёт их
заполнять.

Тест: `tests/test_studio.py::test_service_worker_forgets_previous_user_after_oauth_callback`
— читает отданный сервером `sw.js` и проверяет, что в нём есть регулярка
для `.../callback`, вызывающая `forgetUser()`. Полноценно разыграть
Service Worker (событие `fetch`, `Cache API`) из pytest нельзя — в
отличие от бэкенда, тут нет исполняемой среды JS в тестах (прецедент —
`tests/test_i18n.py`: там то же самое, проверка структуры собранного JS
через regex, не исполнение). Прогнал вручную: без строки с `forgetUser()`
тест падает, с ней — проходит (git stash на `sw.js` и обратно). Полный
прогон (384 теста) зелёный.

## Про GitHub Actions/CI окружение

При подготовке прогона завёл чистый venv, чтобы проверить тесты с нуля —
несколько «падений» (`httpx2`/`httpx`, `scipy`, `soundfile` отсутствовали)
оказались пробелами именно свежего venv, не кода: `pyproject.toml` уже
документирует extras `dev` (`pytest`, `httpx`) отдельной репликой в
комментарии, а `requirements-audio.txt`/`requirements-separation.txt` —
отдельные, намеренно необязательные файлы. После установки всех трёх —
полный прогон (384 теста) зелёный без единой реальной находки там.

## Что не трогал и почему

- **Гипотеза про HPSS и мажорную/минорную терцию** (`docs/findings-chord-quality.md`,
  от 23.09) — по-прежнему не реализована. Попробовал найти способ
  проверить её не на приватных 7 песнях владельца, а на открытом
  датасете — в `scripts/chord_benchmark.py` уже есть готовая обвязка под
  GuitarSet (Zenodo, CC BY 4.0, `mir_eval`). Сетевой policy этого
  окружения блокирует `zenodo.org` (`CONNECT` -> 403, подтверждено через
  `__agentproxy/status`) — скачать датасет из этой сессии не вышло.
  Это не код чинить, а доступ в сеть окружения; если он появится в
  будущем прогоне (или кто-то положит архив в репозиторий/другое
  разрешённое хранилище), GuitarSet даёт проверяемый, открытый эталон
  для этой самой правки, не требующий приватных записей владельца.
- **Конкурентный анализ** — не обновлял в этот прогон (сверка 09.10,
  затем ещё раз зафиксировано 13.10 «следующий прогон подходит»); решил
  приоритизировать разбор вчерашнего свежего коммита (sw.js/favorites),
  который ещё никто не проверял, вместо очередной точечной сверки цен.
  Следующий прогон — хороший момент вернуться к этому (уже два прогона
  подряд откладывается).
- **`localStorage['naslux.nav']`** (`web/static/nav.js`) — при смене
  пользователя на той же вкладке на миг показывает текст предыдущего
  (баланс/подписку), пока не придёт свежий `/api/me` — тот же класс
  проблемы, что в кэше sw.js, но на порядок менее значимый (не данные,
  а строка на экране, которая гарантированно перерисовывается первым же
  вызовом `refreshNav()` при загрузке страницы, без участия сети-таймаута
  на 4 секунды). Не стал чинить отдельно — цена правки (отдельная
  инвалидация) больше, чем то, что она предотвращает.
