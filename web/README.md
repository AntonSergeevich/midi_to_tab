# Веб-приложение

## Запуск

```powershell
python -m pip install -r requirements.txt
python -m pip install -r requirements-web.txt
python -m pip install -r requirements-audio.txt       # распознавание
python -m pip install --no-deps basic-pitch
python -m pip install -r requirements-separation.txt  # разделение дорожек

uvicorn web.app:app --host 0.0.0.0 --port 8000
```

Открыть в браузере:

```
http://localhost:8000
```

**`0.0.0.0` в браузер вводить нельзя.** Это адрес «слушать на всех
интерфейсах» для сервера, а не адрес назначения — браузер ответит
`ERR_ADDRESS_INVALID`. Uvicorn печатает `running on http://0.0.0.0:8000`
и этим сбивает с толку.

Если сервис нужен только на своей машине, понятнее сразу запускать так:

```powershell
uvicorn web.app:app --host 127.0.0.1 --port 8000
```

`--host 0.0.0.0` нужен, только когда к сервису должны подключаться с
других устройств — с телефона в той же сети или из интернета.

### Ключ подписи

```powershell
$env:MIDI2TAB_SECRET = "любая-длинная-случайная-строка"
```

Без него ключ генерируется заново при каждом запуске: куки пользователей
протухают, и счётчик бесплатных песен у всех обнуляется.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `MIDI2TAB_DATA` | папка для базы, загрузок и результатов | `data` |
| `MIDI2TAB_SECRET` | ключ подписи куки; без него генерируется временный, и куки протухают при перезапуске | — |
| `MIDI2TAB_MAX_MB` | предел размера загружаемого файла | `60` |
| `MIDI2TAB_ADMIN_KEY` | ключ входа в админку; без него `/admin` недоступна | — |
| `SMTP_HOST` / `SMTP_PORT` | сервер отправки писем; без него не работает восстановление пароля | — / `465` |
| `SMTP_USER` / `SMTP_PASSWORD` | учётные данные; для Яндекса нужен **пароль приложения**, а не от ящика | — |
| `SMTP_FROM` | адрес отправителя, по умолчанию совпадает с `SMTP_USER` | — |
| `PAYMENT_PROVIDER` | `yookassa` или `getplatinum`; пусто — первый настроенный | — |
| `YOOKASSA_SHOP_ID` / `YOOKASSA_SECRET_KEY` | реквизиты ЮKassa | — |
| `GETPLATINUM_API_URL` | адрес создания платежа из кабинета GetPlatinum | — |
| `GETPLATINUM_SHOP_ID` / `GETPLATINUM_SECRET_KEY` | реквизиты GetPlatinum | — |
| `GETPLATINUM_URL_FIELD` | поле ответа со ссылкой на оплату | `payment_url` |
| `GETPLATINUM_ID_FIELD` | поле ответа с идентификатором платежа | `payment_id` |

Пока реквизиты ЮKassa не заданы, приложение честно пишет, что оплата не
подключена, и не притворяется, будто принимает деньги.

## Как устроено

| Файл | Назначение |
|---|---|
| `app.py` | маршруты FastAPI, загрузка, выдача файлов, вебхук оплаты |
| `jobs.py` | очередь: обработка идёт в пуле потоков, страница опрашивает статус |
| `storage.py` | SQLite: пользователи, задания, платежи |
| `billing.py` | квота бесплатных песен, подписка, провайдер оплаты |
| `static/index.html` | страница загрузки |
| `static/player.html` | плеер с бегущей дорожкой |
| `static/player.js` | синхронизация дорожки со звуком |

## Плеер

Дорожка едет под неподвижной линией воспроизведения. Текущий аккорд
подсвечен, следующий обведён — видно, что играть дальше.

Положение берётся из `currentTime` звука, а не накапливается таймером:
таймер неизбежно уходит от записи, а `currentTime` и есть настоящее
место в ней.

Если на входе был MIDI, играть нечего — браузеры не воспроизводят `.mid`.
В этом случае ноты синтезируются прямо в браузере через Web Audio:
две расстроенные пилы через фильтр с затуханием, похоже на щипок струны.
Никаких сэмплов качать не нужно.

## Учётные записи

Регистрация по почте и паролю, вход, восстановление. Пароли хранятся
как scrypt-хеш с солью: перебор украденной базы стоит дорого, проверка
одного пароля занимает около 100 мс.

Заходить можно и без регистрации — первые две песни доступны анонимно.
Это сознательно: требовать регистрацию до того, как человек увидел
результат, значит терять большую часть посетителей.

**Разобранное до регистрации не теряется.** При регистрации почта
привязывается к текущей анонимной записи, а при входе в существующий
аккаунт свежеразобранные треки переносятся в него.

Защита от подбора: после восьми неудачных попыток вход по этой почте
блокируется на 15 минут. Счёт ведётся по почте, а не по адресу клиента:
адрес легко сменить, а перебор ведут против конкретной записи.

Восстановление: на почту уходит ссылка, действующая час и срабатывающая
один раз. В базе хранится только хеш кода — по украденной базе чужой
пароль не сменить. После смены пароля все прежние коды гасятся.

## Обращения

Форма в личном кабинете. Темы различаются сроком ответа, и срок
показывается в админке: **возврат денег — 10 дней** по закону о защите
прав потребителей, запрос по персональным данным — 10 рабочих дней,
предложения — месяц.

Просроченные обращения выделены красным, за три дня до срока —
янтарным. Счётчик неотвеченных вынесен в сводку. Ответ сохраняется в
кабинете пользователя и, если настроен SMTP, уходит письмом.

## Удаление треков

Кнопка в списке треков. Удаляются и записи в базе, и файлы с диска,
включая партии и табы. Действие необратимое, поэтому спрашивается
подтверждение.

## Админка

Страница `/admin`. Вход по ключу `MIDI2TAB_ADMIN_KEY`; первый вошедший
получает права администратора и безлимит. Без ключа админка недоступна
вообще — это надёжнее пароля по умолчанию, который забывают сменить.

Что можно: выдать безлимит (друзьям, тестировщикам, себе), назначить
администратора, продлить подписку на 30 дней вручную, оставить заметку,
посмотреть сводку по сервису.

Снять права с последнего администратора нельзя — иначе войти больше не
получится.

## Тарифы

Две первые песни бесплатно. Дальше на выбор:

* **19 ₽** — один трек, разово;
* **199 ₽** — месяц без ограничений.

Подписка окупается примерно с одиннадцатого трека. Разница подобрана так,
чтобы постоянным пользователям была выгодна именно она, а разовая покупка
не выглядела наказанием.

Бесплатные пробы расходуются раньше оплаченных треков — иначе купленный
сгорал бы первым. Пробная песня
списывается при постановке в очередь, а не по завершении: иначе один и
тот же файл можно было бы гонять бесконечно, обрывая обработку.

Продление прибавляет дни к остатку, а не обнуляет его — оплата раньше
срока не съедает оплаченное.

### Приём оплаты в России

Stripe и Paddle с российскими юрлицами не работают. Рабочие варианты:
ЮKassa, Робокасса, CloudPayments, Продамус. Принимать платежи можно как
самозанятый или ИП; чек по 54-ФЗ обязателен, ЮKassa умеет пробивать его
сама.

Реализован адаптер ЮKassa: создание платежа и обработка вебхука.
Заменить провайдера — значит написать один класс `PaymentProvider`,
остальное не меняется.

**Проверить на живых платежах я не мог** — нужны реквизиты магазина.
Перед запуском обязательно прогоните тестовый магазин ЮKassa.

## Нагрузка

Замер на процессоре этого сервера:

Замеры на настоящем треке 2:52 (не на синтетическом сигнале):

| Шаг | Время | Скорость | Память |
|---|---|---|---|
| Аккорды из спектра | 12 с | 0,070× | 362 МБ |
| Распознавание нот | 3,8 с | **0,022×** | 729 МБ |
| Разделение на партии | не замерено | около 1× | нужен PyTorch, от 4 ГБ |

Важно мерить установившуюся скорость, а не первый вызов: загрузка модели
занимает несколько секунд и на коротком файле съедает весь замер. Первая
оценка распознавания (0,88×) была именно такой ошибкой — настоящая
скорость в сорок раз выше.

Узкое место — **память, а не процессор**. Один импорт PyTorch добавляет
около 430 МБ, поэтому разделение на партии требовательнее всего
остального вместе взятого. При подписке
199 ₽ это посильно, но стоит ограничить число песен в месяц по-честному
(«справедливое использование»), иначе десяток тяжёлых пользователей
займёт весь сервер.

Пул обработки намеренно небольшой: задачи упираются в процессор, и
десяток параллельных не ускорит ничего, а память съест.


## Требования к сайту в России

Сервис принимает загрузки и оплату, значит подпадает под требования к
операторам персональных данных.

### Что уже сделано в коде

* **Баннер cookie с выбором.** Не просто уведомление, а две кнопки:
  «только необходимые» и «принять все». Аналитика подключается строго
  после согласия — в `consent.js` она висит на событии, которое
  срабатывает лишь при выборе «принять все». Проверено в браузере: при
  отказе событие не возникает.
* **Разделение cookie.** Техническая кука входа необходима для работы
  (без неё не узнать, чьи это треки и сколько разборов осталось) и
  согласия не требует, но описана в политике. Всё остальное — только с
  согласия.
* **Политика конфиденциальности** (`/privacy`) и **публичная оферта**
  (`/offer`) с полями под ваши реквизиты.
* **Хранение в России** — база и файлы лежат там, где запущен сервер.
  При размещении на российском хостинге требование 242-ФЗ выполняется.

### Что нужно сделать вам

1. **Подать уведомление в Роскомнадзор** до начала обработки данных.
   Это не формальность: за работу без уведомления штрафуют.
2. **Заполнить поля** в политике и оферте — они выделены рамкой.
3. **Оформить статус** — самозанятый или ИП — до приёма платежей.
4. **Показать документы юристу.** Шаблоны составлены как рабочая основа
   и юриста не заменяют.
5. **Настроить чеки по 54-ФЗ** — платёжный сервис обычно умеет сам.
6. При утечке данных **уведомить Роскомнадзор** в установленный срок.

[чек-листе Роскомнадзора и ГАРАНТ.РУ](https://www.garant.ru/roskom/trebovaniya-k-saytam-organizaciy-i-ip/)
